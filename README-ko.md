# jay-session

작업을 세션 경계 너머로 옮깁니다.

긴 작업은 컨텍스트 한 창을 넘깁니다. 흔한 해법인 `/compact` 는 정보를 버리는 데다, 하필 컨텍스트가 가장 무거운 — 즉 잃을 게 가장 많은 — 순간에 터집니다. 이 플러그인은 반대로 갑니다. **지우기 전에** 남길 것을 적어두고, 다음 세션이 그걸 자동으로 이어받게 합니다.

## 설치

```bash
claude plugin marketplace add jaymunsh/jay-claude
claude plugin install jay-session@jay-claude
```

첫 명령이 이 저장소를 clone 하고, 두 번째가 거기서 플러그인을 설치합니다. 설치 후 Claude Code를 재시작하세요 — 명령어와 훅은 세션 시작 시점에 로드됩니다.

`python3` 이 필요하며 macOS와 대부분의 리눅스에 기본 포함돼 있습니다. **한 번만 설치하면 모든 프로젝트에서 쓸 수 있습니다** — 프로젝트마다 설치할 필요 없습니다.

나중에 갱신하려면:

```bash
claude plugin marketplace update jay-claude
```

## 핵심 흐름

직접 치는 명령 두 개와, 알아서 되는 것 하나.

```
── 세션 1 ─────────────────────────────────────
  (한참 작업)

  > /jay-new

    대화와 git 상태를 훑어
    .claude/session/handoff-20260807-1430.md 작성.
    정말로 추론이 안 되는 것만 물어봅니다.

  > /clear                     ← 이건 직접 칩니다

── 세션 2 ─────────────────────────────────────
  (인계 문서가 이미 컨텍스트에 들어와 있음)

  > 이어서 해줘  /  고  /  아무 말이나

    git status로 인계 문서가 지금도 맞는지 확인하고,
    몇 줄로 브리핑한 뒤 다음 할 일부터 시작합니다.
```

**안 해도 되는 것:** 인계 문서 파일명 찾기, 뭘 만들던 중이었는지 다시 설명하기, 미리 준비한 프롬프트 붙여넣기. 이미 컨텍스트에 다 있습니다. 첫 메시지는 두 글자여도 됩니다.

**여전히 하는 것:** `/clear` 직접 입력, 그리고 새 세션에서 **아무 메시지나 한 번** 보내기. 세션은 입력을 기다리며 가만히 있고, 컨텍스트가 채워졌다고 제가 먼저 말을 걸지는 않습니다. 요점은 타이핑을 0으로 만드는 게 아니라, **그 타이핑이 더 이상 정보를 담지 않아도 된다**는 것입니다.

### `/clear` 가 자동이 아닌 이유

`/clear` 는 대화를 통째로 버립니다. 슬래시 명령은 사용자 입력으로만 실행되고 훅도 세션을 지우지 못합니다 — 설령 가능했더라도 이건 타이밍을 사람이 정해야 하는 결정입니다.

## 명령어

| 명령 | 하는 일 | 사전 준비 |
|---|---|---|
| `/jay-new` | 인계 문서 작성 후 `/clear` 안내 | 없음. 폴더도 알아서 만듭니다 |
| `/jay-init` | 이 프로젝트의 devlog 자동 기록 켜기 | 없음 |

범위를 좁힐 수도 있습니다: `/jay-new 인증 리팩터링만`

### 인계 문서에 담기는 것

목표, 지금까지 한 것, 현재 상태(브랜치·미커밋 변경·검증 여부), 재개할 때 제일 먼저 돌려볼 명령, 다음 할 일, 그리고 무엇보다 **시도했다 안 된 것**.

마지막 항목이 이 문서의 존재 이유입니다. 무엇이 바뀌었는지는 `git log` 가 이미 알려줍니다. **어떤 접근을 포기했고 왜 포기했는지**는 인계 문서에만 남고, 그게 다음 세션이 같은 벽에 다시 박는 걸 막아줍니다.

## 개발일지 devlog (선택)

매 턴의 요청·결과·변경 파일이 쌓이는 추가 전용 기록입니다. 회고와 "지난달에 그거 어떻게 고쳤더라"에 쓰입니다.

```
/jay-init
```

**이것만 명시적 동의를 받습니다.** 매 턴 파일이 쌓이는 동작이라, 묻지도 않았는데 저장소에 파일이 늘어나면 안 되기 때문입니다. devlog를 쓸 프로젝트마다 한 번씩 쳐주세요.

기록은 **켠 다음 턴부터** 시작합니다. 세션 도중에 켜도 그 세션 앞부분은 복구되지 않고, 프로젝트의 과거 이력을 소급해서 채우지도 않습니다.

### 읽는 법

명령어가 필요 없습니다. 그냥 물어보세요.

- *"지난주에 그 타임아웃 에러 어떻게 고쳤지?"* → devlog 검색
- *"이번 주에 뭐 했지?"* → 시간순 나열이 아니라 주제별로 묶어 요약

### 결정 기록

실제로 선택이 있었던 항목에는 `**결정:**` 을 태그하고, **고른 것·버린 것·이유**를 함께 적습니다.

```markdown
## 2026-08-07 17:22 — 인증 방식 확정
**결정:** JWT 대신 서버 세션 — JWT는 즉시 무효화가 안 돼 로그아웃 요구사항과
충돌. 확장은 Redis로 감당.
```

나중에 결정만 뽑아보려면:

```bash
grep -B4 '^\*\*결정:' .claude/session/devlog*.md
```

별도 `decisions.md` 를 두지 않은 건 의도적입니다. 기록 위치가 한 곳이면 "이건 어디 쓰지"를 매번 판단하지 않아도 되고, 그 결정이 어떤 작업 중에 나왔는지가 앞뒤 항목에 같이 남습니다.

### 수동 기록

훅은 눈에 보이는 것만 뽑아냅니다. 그게 못 잡는 것 — 왜 그 방식을 골랐는지, 어디서 막혔는지, 뒤늦게 알게 된 제약 — 이 중요할 때는 *"이건 남겨줘"* 라고 하면 그 판단 근거까지 함께 기록됩니다.

## 생기는 파일

**요청하기 전까지는 아무것도 안 생깁니다.** `/jay-new` 가 처음 쓰일 때 폴더를 만들고, devlog 훅은 `devlog.md` 가 없으면 즉시 종료합니다.

```
<프로젝트>/.claude/session/
├── handoff-20260807-1430.md   # 누적. 가장 최근 것을 사용
├── devlog.md                  # 이번 달. 이 파일 존재 여부가 켜짐/꺼짐 스위치
├── devlog-2026-07.md          # 지난 달들, 자동 분리
└── .devlog-state              # 훅 중복 방지 커서
```

이 폴더를 처음 만들 때 `.gitignore` 에 `.claude/session/` 을 넣을지 **한 번만** 물어봅니다. 기본은 넣기 — 개인 작업 흐름이라 커밋 로그와 중복되고, devlog는 매 턴 커져 diff를 오염시킵니다. 팀과 인계 문서를 공유할 목적이면 빼세요.

## 동작 원리

훅 3개, 스크립트 1개.

| 훅 | 발동 시점 | 하는 일 |
|---|---|---|
| `Stop` | 매 턴 종료 | devlog에 append, 월별 자동 분리. devlog가 꺼져 있으면 즉시 종료 |
| `SessionStart` (`clear`, `compact`) | 지운 뒤 새 세션 시작 | 30분 내 작성된 인계 문서를 주입 |
| `PreCompact` | 컨텍스트 압축 직전 | 압축 전 원본 대화 파일 위치를 기록 |

**30분 제한**이 자동 인계의 소음을 막는 장치입니다. 인계 문서를 방금 썼다는 것 자체가 "이어서 하겠다"는 신호라, 지난주 문서가 무관한 세션에 끌려 들어오지 않습니다.

**`PreCompact` 가 사본이 아니라 경로만 남기는 것**도 의도적입니다. 압축은 모델의 컨텍스트만 지우고 대화 파일은 디스크에 그대로 남습니다. 그러니 사후에 필요한 건 복사본이 아니라 원본을 가리키는 주소입니다.

**스킬과 훅을 나눈 기준**은 "잊힐 수 있는가"입니다. 판단이 필요한 일(인계 문서에 뭘 담을지, 검색 결과를 어떻게 요약할지)은 `session-manager` 스킬에 두었고, 기계적인 일은 훅에 두었습니다. "매 턴 기록해야지" 같은 지시는 세션이 길어지면 조용히 안 지켜지는 대표적인 종류라서요.

## 끄기

```bash
rm .claude/session/devlog.md    # devlog 기록 중단
claude plugin uninstall jay-session@jay-claude
```

`devlog.md` 를 지우면 기록도 함께 사라집니다. 남길 게 있으면 먼저 옮기세요. 플러그인을 제거하면 훅과 명령어가 사라지고, 이미 쓰인 `.claude/session/` 파일은 그대로 남습니다.

## 참고

- 사용자의 `settings.json` 을 건드리지 않습니다. 훅이 플러그인 안에 실려 있어서 다른 플러그인·훅과 충돌하지 않습니다.
