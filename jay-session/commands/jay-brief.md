이 프로젝트가 **무엇이고 어떻게 생겼는지**를 파일 하나로 정리한다. 받는 쪽은 다른 프로젝트에서 일하는 에이전트다 — 이 저장소를 열어본 적도, 이 대화를 본 적도 없다.

`/jay-new` 와 혼동하지 말 것. 그건 *내가 하던 작업*을 다음 세션에 넘기는 문서고, 이건 *프로젝트 자체*를 밖으로 설명하는 문서다. 진행 중인 작업은 여기서 맨 마지막 한 절이다.

인자를 받지 않는다. 프로젝트 하나당 문서 하나다.

## 이 문서의 규칙

**혼자 완결돼야 한다.** 받는 쪽은 이 저장소를 안 갖고 있을 수 있다. `README.md 참고`, `CLAUDE.md 참고` 같은 포인터는 거기서 열 수 없는 주소라 쓸모가 없다. `CLAUDE.md` 와 `README.md` 는 **재료로 읽되 내용은 이 파일에 담는다.** 통째로 복사하라는 뜻은 아니고, 밖에서 이해되게 추려 넣으라는 뜻이다.

## 절차

**0. 파일이 이미 있으면 먼저 읽는다.** 갱신이지 재작성이 아니다. 어느 절을 새로 만들고 어느 절을 이어받는지는 아래 "다시 실행할 때"에 있다.

**1. 저장소를 읽는다.** 대화보다 저장소가 먼저다. 받는 쪽이 알아야 하는 건 대부분 여기 있다.

```bash
git ls-files                       # 구조. ls 와 달리 gitignore 가 이미 반영됨
git log --oneline -20              # 최근 흐름
git log --stat -5                  # 최근 커밋이 어디를 건드렸나
git status --short                 # 미커밋
git branch --show-current
```

git 저장소가 아니면 구조는 `ls -R`(숨김·의존성 폴더 제외)로 대신하고 "최근 흐름" 절은 통째로 뺀다. 없는 절을 빈칸으로 남기지 않는다.

그리고 `README.md`, `CLAUDE.md` / `AGENTS.md`, 패키지 매니페스트(`package.json`, `pyproject.toml`, `Cargo.toml` 등)를 읽는다. 실행·테스트 명령은 대부분 여기 적혀 있다. **추측해서 쓰지 말고 실제로 확인한 명령만 적는다.**

**2. 이 플러그인이 이미 쌓아둔 것을 읽는다.** 이 문서에서 값어치 있는 두 절("아키텍처와 설계 결정", "함정")의 재료가 정확히 여기 있다. 대화에서만 가져오면, 그 결정들을 겪지 않은 세션이 이 명령을 칠 때 문서가 얇아진다.

```bash
# 글롭을 셸이 아니라 grep 이 처리한다 — zsh 는 매치가 없으면 명령 자체를 실패시킨다
grep -rh -A4  --include='devlog*.md'   '^\*\*결정:' .claude/session/   # → "아키텍처와 설계 결정"
grep -rh -A20 --include='handoff-*.md' '^## 함정'    .claude/session/   # → "함정"
```

**둘 다 없는 게 정상인 경로다.** devlog는 `/jay-init` 으로 켜야 쌓이고 handoff는 `/jay-new` 를 쳐야 생긴다. 없으면 조용히 넘어가고, 그 사실을 문서에 적지 않는다.

읽은 것을 그대로 옮기지 않는다. devlog 항목은 그날의 작업 기록이고 handoff는 그 시점의 스냅샷이라, 지금도 유효한지는 저장소로 확인해야 한다. **이미 뒤집힌 결정은 "예전엔 이랬고 지금은 이렇다"로 적는다** — 뒤집혔다는 사실 자체가 다음 사람에게 값어치 있다.

**3. 문서를 쓴다** → `.claude/session/project-brief.md`

디렉터리가 없으면 만든다. `.gitignore` 는 이 명령에서 묻지 않는다 — 이 파일은 밖으로 들고 나가는 용도라 커밋 여부와 무관하고, 그 질문은 `/jay-new` 와 `/jay-init` 이 이미 한다.

```markdown
# <프로젝트명> — 프로젝트 브리프

생성 2026-08-07
최종 갱신 2026-08-07

## 한 줄 요약

## 무엇을 하는 프로젝트인가
왜 존재하는지까지. 무엇을 하는지만 적으면 받는 쪽이 판단을 못 한다.

## 구조
주요 폴더와 핵심 파일. 전체 트리를 붙이지 말고 들어갈 지점을 짚어준다.

## 돌리는 법
설치, 실행, 테스트. 실제로 확인한 명령만.

## 아키텍처와 설계 결정
왜 이 구조인지, 무엇을 버렸는지, 어디를 건드리면 무너지는지.
코드를 읽어도 안 나오고 대화·커밋 메시지에만 있는 것들.

## 함정 / 알아둘 것
시도했다 안 된 것, 헷갈리기 쉬운 것, 먼저 알았으면 좋았을 것.

## 최근 흐름
git log 20개의 요약. 커밋 나열이 아니라 "최근 어느 방향으로 움직였나".

## 지금 진행 중인 것
짧게. 자세한 작업 인계는 /jay-new 의 몫이다.
```

**절 순서는 얕은 것부터다.** 받는 쪽이 위에서부터 읽다가 충분해지면 멈출 수 있어야 한다. "뭐 하는 건지 알고 일단 돌려보자"가 가장 흔한 진입이라 `돌리는 법`이 깊은 설명보다 앞에 오고, `최근 흐름`은 배경 지식이라 뒤로 간다. 순서를 바꾸고 싶어지면 이 이유를 먼저 반박할 것.

절 제목은 고정이 아니다. 프로젝트에 해당 없는 절은 빼고, 필요한 절은 더한다. 빈 절을 남기는 게 제일 나쁘다.

**4. 마무리 출력.** 절대경로를 박은 복붙 프롬프트를 준다. 받는 쪽은 다른 프로젝트에서 일하므로 작업 폴더가 다르고, 상대경로는 거기서 아무 의미가 없다. `pwd` 로 실제 경로를 확인해서 쓴다.

> ```
> /Users/me/projects/foo/.claude/session/project-brief.md 읽고 이 프로젝트 파악해줘.
> ```

새로 만든 건지 갱신한 건지 한 줄로 알린다. 갱신이면 무엇이 바뀌었는지도 한 줄.

## 다시 실행할 때

**통째로 덮어쓰지 않는다.** 절마다 성격이 다르다.

| 절 | 처리 |
|---|---|
| 구조 / 최근 흐름 / 지금 진행 중인 것 | **새로 만든다** — git 에서 뽑으니 최신이 맞다 |
| 한 줄 요약 / 무엇을 하는 프로젝트인가 / 돌리는 법 | 실제로 바뀐 것만 고친다 |
| **아키텍처와 설계 결정 / 함정** | **이어받고 덧붙인다. 절대 날리지 않는다** |

마지막 두 절이 이 문서에서 유일하게 저장소로 복구할 수 없는 부분이다. 2단계의 devlog·handoff 가 일부는 메워주지만 그 둘도 없을 수 있고, 있어도 브리프에만 적힌 판단까지 담고 있지는 않다. 새로 쓰면 그때까지 쌓인 것이 사라진다.

기존 항목이 지금은 틀렸다면 지우지 말고 **왜 더 이상 맞지 않는지 한 줄 붙인다.** "이건 예전에 이랬다"가 다음 사람을 같은 벽에서 구해낸다.

`생성` 은 그대로 두고 `최종 갱신` 만 바꾼다.
