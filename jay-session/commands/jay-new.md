`session-manager` 스킬의 "1. 인계(handoff)" 절차를 그대로 수행한다.

`.claude/session/` 이 없으면 그 자리에서 만든다. 이 명령을 친 것 자체가 "여기에 인계 문서를 남겨라"는 의사표시라, 별도 활성화 단계를 요구하지 않는다. 다만 `.gitignore` 에 `.claude/session/` 이 없으면 **한 번만** 묻는다 — 저장소에 뭘 커밋할지는 사용자가 정할 몫이다.

devlog 자동 기록은 여기서 켜지 않는다. 매 턴 파일이 쌓이는 동작이라 명시적 동의가 필요하고, 그건 `/jay-init` 의 몫이다.

핵심만 다시 새기면:

- **먼저 다 쓰고, 나중에 묻는다.** 대화에 다음 스텝이 이미 거의 다 들어있다. 먼저 "다음에 뭐 하실 건가요"라고 물으면 사용자가 없는 답을 짜내야 한다. 추론 가능한 것을 전부 채운 뒤, 정말 모르는 것만 한 번에 확인한다. 확인할 게 없으면 묻지 않고 끝낸다.
- **새 세션의 나는 이 대화를 전혀 모른다.** 파일 경로·함수명·명령을 그대로 적는다. "그 함수", "아까 그 파일"은 다음 세션에서 아무 의미가 없다.
- **"함정 / 배운 것"이 이 문서의 진짜 값어치다.** 무엇을 했는지는 git log에도 남지만, 무엇을 시도했다 실패했는지는 여기에만 남는다.

$ARGUMENTS 가 있으면 인계 문서의 초점으로 쓴다 (예: `/jay-new 인증 리팩터링만`).

문서를 쓴 뒤 마무리 안내:

> handoff 작성했습니다: `.claude/session/handoff-....md`
> `/clear` 치시면 새 세션이 이 문서를 읽고 이어서 시작합니다.

`/clear` 는 대화를 버리는 동작이라 사람이 직접 친다. 대신 실행하겠다고 제안하지 않는다.
