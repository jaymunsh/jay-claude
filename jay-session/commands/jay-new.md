`session-manager` 스킬의 "1. 인계(handoff)" 절차를 그대로 수행한다.

`.claude/session/` 이 없으면 그 자리에서 만든다. 이 명령을 친 것 자체가 "여기에 인계 문서를 남겨라"는 의사표시라, 별도 활성화 단계를 요구하지 않는다. 다만 `.gitignore` 에 `.claude/session/` 이 없으면 **한 번만** 묻는다 — 저장소에 뭘 커밋할지는 사용자가 정할 몫이다.

devlog 자동 기록은 여기서 켜지 않는다. 매 턴 파일이 쌓이는 동작이라 명시적 동의가 필요하고, 그건 `/jay-init` 의 몫이다.

핵심만 다시 새기면:

- **먼저 다 쓰고, 나중에 묻는다.** 대화에 다음 스텝이 이미 거의 다 들어있다. 먼저 "다음에 뭐 하실 건가요"라고 물으면 사용자가 없는 답을 짜내야 한다. 추론 가능한 것을 전부 채운 뒤, 정말 모르는 것만 한 번에 확인한다. 확인할 게 없으면 묻지 않고 끝낸다.
- **새 세션의 나는 이 대화를 전혀 모른다.** 파일 경로·함수명·명령을 그대로 적는다. "그 함수", "아까 그 파일"은 다음 세션에서 아무 의미가 없다.
- **"함정 / 배운 것"이 이 문서의 진짜 값어치다.** 무엇을 했는지는 git log에도 남지만, 무엇을 시도했다 실패했는지는 여기에만 남는다.

$ARGUMENTS 가 있으면 그게 **다음 세션의 주제**다. "다음에 할 일"을 이걸 1번으로 놓고 다시 세우고, "목표"도 여기에 맞춘다 (예: `/jay-new 라이브 검증 마무리`). 나머지 절은 그대로 채운다 — 초점을 준 것이지 다른 맥락을 버리라는 뜻이 아니다. 주제가 지금까지 한 작업과 무관하면 짚고 넘어간다.

## 다른 세션·에이전트에게 넘기는 경우

$ARGUMENTS 가 "다른 세션에 넘김", "에이전트한테 전달", "인수인계" 처럼 **읽는 쪽이 내가 아님**을 뜻하면 두 가지가 달라진다.

**저장 위치를 `docs/handoff-<주제>.md` 로 바꾼다.** `.claude/session/` 은 보통 `.gitignore` 라서 다른 clone·다른 머신에서는 파일이 보이지도 않는다. 파일명도 타임스탬프 대신 주제를 쓴다 — 사람이 골라 건네는 문서라 정렬이 아니라 이름으로 찾는다. `docs/` 가 없으면 만든다. 커밋할지는 사용자가 정하므로 대신 커밋하지 않고, 경로만 알린다.

**프로젝트 오리엔테이션 절을 맨 앞에 넣는다.** 처음 오는 쪽은 작업 맥락 이전에 프로젝트 자체를 모른다. 다만 **저장소를 읽어서 알 수 있는 것은 옮겨 적지 않는다** — "함정 / 배운 것"이 값어치 있는 이유와 같다. 중복은 어긋나기 시작하는 순간 둘 중 뭐가 맞는지 아무도 모르게 된다.

- `CLAUDE.md` / `AGENTS.md` 가 있으면 **내용을 복사하지 말고 가리킨다.** Claude Code는 그 프로젝트에서 이걸 자동으로 읽으므로 받는 쪽은 이미 갖고 있다. 한 줄이면 된다: `프로젝트 규약은 CLAUDE.md 참고.`
- 없으면 최소한만 직접 적는다 — 이 프로젝트가 뭘 하는 것인지 2줄, 주요 폴더 구조, 설치·실행·테스트 명령. 그리고 `/init` 로 `CLAUDE.md` 를 만들어 두면 다음부터 이 절이 필요 없어진다고 한 줄 덧붙인다.
- **아키텍처와 설계 결정은 저장소에 안 적혀 있는 것만 쓴다.** 왜 이 구조를 골랐는지, 무엇을 버렸는지, 어디를 건드리면 무너지는지 — 코드를 읽어도 안 나오고 대화에서만 나온 것들이다. README에 이미 있는 설명을 옮겨 적지 않는다.
- **범위와 경계**를 적는다. 어디까지 건드려도 되고 어디는 내가 잡고 있는지. 넘겨받는 쪽은 이걸 모르면 같은 파일을 동시에 고친다.
- 경로는 전부 **저장소 기준 상대경로**로 쓴다. `/Users/...` 는 다른 머신에서 무의미하다.

문서를 쓴 뒤 오래된 인계 문서를 정리한다 — `.claude/session/` 의 최근 10개만 남긴다. `docs/` 로 넘긴 문서는 건드리지 않는다. 이름 붙여 건넨 것이라 쌓이지 않고, 지우는 건 사용자 몫이다.

```bash
ls -t .claude/session/handoff-*.md | tail -n +11 | xargs rm -f --
```

지운 게 있으면 마무리 보고에 한 줄로 언급한다. 조용히 지우면 나중에 "분명 있었는데"가 된다.

마지막 출력은 **복붙용 프롬프트 한 덩어리뿐**이다. 파일명에 타임스탬프가 들어가 외울 수 없고 `/clear` 직후엔 확인할 방법도 사라지므로 실제 파일명을 박아 넣되, 그 외의 설명·요약·안내는 붙이지 않는다. `/clear` 직전이라 어차피 다 버려지는 토큰이다.

지운 handoff가 있으면 그 한 줄만 위에 덧붙인다.

> ```
> .claude/session/handoff-20260807-1430.md 읽고 검증한 뒤 이어서 진행해줘.
> ```

프롬프트에 `git status` 를 박지 않는다. git 저장소인지 아닌지에 따라 문구가 갈리면 사용자가 외울 게 늘고, 어차피 검증 방법은 인계 문서의 "재개 검증" 절과 `session-manager` 스킬이 알고 있다.

`/clear` 는 대화를 버리는 동작이라 사람이 직접 친다. 대신 실행하겠다고 제안하지 않는다.

넘김 모드에서는 `/clear` 가 없다. 프롬프트도 받는 쪽이 칠 것이므로 경로를 `docs/` 것으로 바꾸고, 이 세션은 그대로 이어진다 — 지우라고 안내하지 않는다.
