# Session Manager

긴 작업을 세션 경계 너머로 옮기는 스킬. 네 가지 일을 한다: **인계(handoff)**, **복귀(resume)**, **개발일지(devlog)**, **프로젝트 브리프(brief)**.

## 무엇이 동의를 필요로 하는가

기준은 **누가 시작했는가**다.

- **사용자가 요청한 것**(handoff 작성, 수동 기록, 검색)은 요청 자체가 동의다. `.claude/session/` 이 없으면 그 자리에서 만들고 진행한다. 별도 활성화 단계를 요구하면 아무 판단도 없는 관문만 하나 세우는 셈이다.
- **알아서 굴러가는 것**(devlog 자동 기록)은 다르다. 매 턴 파일이 쌓이는 동작이라 `/jay-init` 으로 명시적으로 켜기 전에는 훅이 즉시 종료한다. 묻지도 않았는데 남의 저장소에 파일이 쌓이기 시작하면 신뢰가 깨진다.

## 파일 위치

모든 파일은 프로젝트 루트의 `.claude/session/` 에 둔다. 이미 존재하는 `.claude/` 관례를 재사용하는 것이고, 별도 숨김 폴더를 새로 만들지 않는다.

```
.claude/session/
├── handoff-YYYYMMDD-HHMM.md   # 인계 문서 (여러 개 누적)
├── project-brief.md            # 프로젝트 브리프 (하나만, 계속 갱신)
├── devlog.md                   # 이번 달 개발일지 (append only)
├── devlog-YYYY-MM.md           # 지난 달들 (훅이 자동 분리)
└── .devlog-state               # 훅 중복 방지용 커서 (신경 쓸 것 없음)
```

### 데이터 수명

| 대상 | 정책 | 이유 |
|---|---|---|
| handoff | **최근 10개만** 유지, 새로 쓸 때 초과분 삭제 | 복귀는 언제나 최신 하나만 읽는다. 그 이상은 쌓이기만 한다 |
| project-brief | **하나만** 유지, 다시 쓸 때 갱신 | 프로젝트당 하나면 충분하고, 여러 판본이 있으면 어느 게 맞는지 모른다 |
| devlog | **영구 보존**, 월별로 분리만 | 회고와 트러블슈팅의 값어치가 "오래된 기록"에서 나온다. 지울 이유가 없다 |

devlog는 합쳐지지 않는다. 월이 바뀔 때 **쪼개지기만** 한다. 검색은 `devlog*.md` 로 전체를 훑으므로 쪼개져 있어도 상관없고, 한 파일이 무한정 커지는 것만 막힌다.

`.claude/session/` 을 처음 만들 때 `.gitignore` 에 항목이 없으면 **한 번만** 묻는다. 기본은 등록(개인 작업 흐름이라 커밋 로그와 중복되고, devlog가 매 턴 커져 diff를 오염시킨다)이지만, 팀과 인계 문서를 공유할 목적이면 커밋하는 게 맞다. 이미 물어봤거나 항목이 있으면 다시 묻지 않는다.

## 명령어

| 명령 | 하는 일 | 사전 준비 |
|---|---|---|
| `/jay-new` | handoff 작성 → `/clear` 안내 | 없음. 폴더도 알아서 만든다 |
| `/jay-init` | devlog 자동 기록 켜기 | 없음 |
| `/jay-brief` | 프로젝트 브리프 작성·갱신 | 없음 |

복귀·검색·수동 기록은 명령어가 따로 없다. "이어서 하자", "지난주에 그거 어떻게 고쳤지", "이건 남겨줘" 처럼 말하면 이 스킬이 처리한다. `/clear` 자동 인계도 handoff만 있으면 동작하며 devlog와는 무관하다.

## 1. 인계 (handoff)

`/jay-new`, 또는 사용자가 `/clear`·새 세션·컨텍스트 정리를 언급하면 이걸 한다.

**핵심: 먼저 쓰고, 나중에 묻는다.** 대화에 이미 다음 스텝이 거의 다 암시돼 있다. 먼저 "다음에 뭐 하실 건가요?"라고 물으면 사용자가 없는 답을 짜내야 한다. 대화에서 추론 가능한 것을 전부 채운 초안을 만든 뒤, **정말로 추론이 안 되는 항목만** 한 번에 확인한다. 확인할 게 없으면 묻지 말고 끝낸다.

### 절차

1. **대화를 되짚는다.** 무엇을 하려 했고, 어디까지 갔고, 무엇이 막혔는지. 파일 경로와 함수명은 정확히 — 새 세션의 나는 이 대화를 전혀 모른다.
2. **작업 트리 상태를 확인한다.** `git status --short` 와 `git log --oneline -5`. 커밋 안 된 변경이 있으면 그게 인계의 핵심이다.
   git 저장소가 아니면(`git rev-parse --git-dir` 실패) 이 단계를 건너뛰고, 인계 문서의 git 관련 항목도 빼고, 재개 프롬프트에도 git 검증 구절을 넣지 않는다. 없는 것을 확인하라고 시키면 다음 세션이 에러 하나를 보고 시작할 뿐이다.
3. **`.claude/session/handoff-YYYYMMDD-HHMM.md` 를 쓴다.** 아래 템플릿. 디렉터리가 없으면 만들면서 `.gitignore` 를 한 번 확인한다(위 "파일 위치").

   파일명의 시각은 **반드시 `date "+%Y%m%d-%H%M"` 를 실행해서 쓴다.** 짐작해서 적지 않는다. 실제로 01:06에 쓴 문서에 `2115` 가 박힌 적이 있고, 정렬이 mtime 기준이라 훅은 멀쩡히 돌아서 아무도 못 잡았다. 파일명만 보면 순서가 거꾸로 보인다.
4. **오래된 인계 문서를 정리한다.** 최근 10개만 남긴다:
   ```bash
   ls -t .claude/session | grep '^handoff-' | tail -n +11 | xargs -I{} rm -f .claude/session/{}
   ```
   복귀할 때 읽는 건 언제나 최신 하나뿐이라 그 이상은 쌓이기만 한다. 지운 개수가 있으면 마무리 보고에 한 줄로 언급한다 — 조용히 지우면 나중에 "분명 있었는데"가 된다.
5. **불확실한 것만 확인한다.** "다음 단계를 A로 적었는데 맞나요?" 정도. 전부 다 되물으면 인계의 의미가 없다.
6. **새 세션용 프롬프트를 출력한다.** 복사해서 바로 붙여넣을 수 있는 형태로, 코드블록 하나에.

### handoff 템플릿

```markdown
# Handoff — {한 줄 요약} ({YYYY-MM-DD HH:MM})

## 목표
{이 작업이 궁극적으로 뭘 달성하려는 건지 1~2문장}

## 지금까지 한 것
- {변경한 파일:라인 과 무엇을 왜 바꿨는지}

## 현재 상태
- 브랜치: {branch}                        ← git 저장소일 때만
- 커밋 안 된 변경: {git status 요약, 없으면 "없음"}   ← git 저장소일 때만
- 동작 확인: {테스트/실행 결과. 안 돌려봤으면 "미검증"이라고 솔직히}
- 재개 검증: `{pytest tests/auth -x 처럼, 새 세션이 제일 먼저 돌려볼 명령}`

## 다음에 할 일
1. {구체적으로. "리팩터링 계속"이 아니라 "src/auth.py:42 의 토큰 만료 처리 추가"}

## 함정 / 배운 것
- {막혔던 지점, 시도했다 실패한 접근, 알아낸 제약. 이게 없으면 다음 세션이 같은 벽에 다시 박는다}

## 참고
- {읽어야 할 파일, 링크, 이슈 번호}
```

"함정" 섹션이 인계 문서의 진짜 값어치다. 무엇을 했는지는 git log로도 알 수 있지만, **무엇을 시도했다 실패했는지**는 이 문서에만 남는다.

### 파일을 쓴 뒤

**항상 복붙용 프롬프트를 함께 준다.** SessionStart 훅이 걸려 있으면 `/clear` 후 아무 말이나 해도 되지만, 훅이 안 걸리는 경우(플러그인 비활성, 다른 환경, 세션을 지우지 않고 나중에 재개)가 있고 사용자가 그걸 매번 판단하게 만들 이유가 없다. 프롬프트가 한 줄 남아 있으면 어느 쪽이든 동작한다.

파일명에 타임스탬프가 들어가 외울 수 없으므로, **정확한 경로를 박아서** 준다. 그리고 그 한 줄만으로 완결되게 쓴다 — 스킬 트리거나 훅 주입에 기대지 않아야 어떤 상황에서도 동작한다.

마무리 출력은 **이 한 덩어리뿐**이다. 설명·요약·안내를 붙이지 않는다 — 바로 `/clear` 로 버려질 토큰이다.

> ```
> .claude/session/handoff-20260807-1430.md 읽고 검증한 뒤 이어서 진행해줘.
> ```

프롬프트에 `git status` 를 박지 않는다. git 저장소인지에 따라 문구가 갈리면 사용자가 외울 게 늘고, 검증 방법은 인계 문서의 "재개 검증" 절과 이 스킬이 이미 알고 있다.

다음 할 일이 뚜렷하면 프롬프트 끝에 한 구절만 덧붙인다: `다음 할 일 1번(토큰 만료 처리)부터.`

전체 맥락을 프롬프트에 다시 욱여넣지 말 것. 파일을 가리키는 게 훨씬 싸고 정확하며, 문서와 프롬프트가 어긋날 여지도 없다.

`/clear` 는 대화를 버리는 동작이라 사람이 직접 친다. 대신 치겠다고 제안하지 말 것.

## 2. 복귀 (resume)

`/clear` 직후라면 훅이 최신 handoff의 **경로**를 이미 넣어뒀다. 본문은 안 들어있으니 읽는 것부터 시작한다. 훅이 안 걸린 세션에서 "이어서 하자", "지난번 거 계속" 같은 말이 나오면 1번부터 찾는다:

1. `ls -t .claude/session/ 2>/dev/null | grep '^handoff-' | head -3` 으로 최근 인계 문서를 찾는다. 없으면 여기서 끝이다 — 인계 문서가 없는 프로젝트에서 부른 것이니 사용자에게 그렇게 말하고 `/jay-new` 를 안내한다. (셸 글롭을 안 쓰는 이유: zsh 는 매치가 없으면 명령 자체를 실패시킨다.)
2. 가장 최근 것을 읽는다.
3. **문서가 지금도 맞는지 검증한다.** git 저장소면 `git log --oneline` 과 `git status` 로 그 뒤에 무슨 일이 있었는지 확인한다. 인계 문서는 쓰인 시점의 스냅샷이라, 그 사이 다른 세션이 작업을 진행했을 수 있다. git이 없으면 문서에 적힌 "재개 검증" 명령을 돌려보거나 해당 파일을 직접 읽어 확인한다.
4. 3~5줄로 브리핑하고 다음 할 일을 제안한다. 문서 전체를 사용자에게 다시 읽어주지 말 것.

## 3. 개발일지 (devlog)

`.claude/session/devlog.md` 에 턴 단위 기록이 쌓인다. **append only** — 과거 항목은 절대 수정하거나 삭제하지 않는다. 회고와 트러블슈팅에서 값어치가 나오는 이유가 "그때 실제로 무슨 일이 있었는가"의 무편집 기록이기 때문이다.

### 켜는 법

기록은 훅이 자동으로 한다. 모델이 "매번 기록해야지"를 기억하는 방식은 세션이 길어지면 반드시 새기 때문에, harness에 맡긴다.

훅은 플러그인(`jay-session`)에 함께 실려 있으므로 사용자의 `settings.json` 을 손댈 일이 없다. **켜고 끄는 스위치는 `.claude/session/devlog.md` 파일의 존재 여부다** — 없으면 훅이 즉시 종료한다. `/jay-init` 에서 이 파일을 만들지 정한다.

나중에 마음이 바뀌면:

```bash
touch .claude/session/devlog.md   # 켜기
rm .claude/session/devlog.md      # 끄기 (기존 기록을 지우게 되니 먼저 옮길지 확인)
```

각 훅이 하는 일:

| 이벤트 | 하는 일 |
|---|---|
| `Stop` | 끝난 턴을 devlog에 append. 월이 바뀌면 지난 달치를 `devlog-YYYY-MM.md` 로 분리 |
| `PreCompact` | 압축 시점과 압축 전 원본 transcript 경로를 devlog에 남김 |
| `SessionStart` | `/clear` 직후 최신 handoff의 **경로와 나이**("31일 전")만 주입. 본문은 필요할 때 읽는다 |

`PreCompact` 가 스냅샷이 아니라 경로만 남기는 이유: 압축은 모델의 컨텍스트만 지우고 transcript 파일은 디스크에 그대로 남는다. 그래서 보험으로 필요한 건 사본이 아니라 "원본이 어디 있는지"다. auto-compact가 예고 없이 터진 뒤에도 되짚어 갈 길이 생긴다.

`/jay-init` 으로 devlog를 켠 직후에는 알려준다: 훅은 **다음 턴부터** 기록하며, 이미 지나간 이번 세션의 앞부분은 남지 않는다.

### 읽는 법

"지난주에 그 에러 어떻게 고쳤지", "이 파일 왜 이렇게 됐지" 같은 질문에는 devlog를 검색한다. 기록만 쌓고 안 읽으면 아무 값어치가 없다. 월별로 분리되므로 glob으로 전체를 훑는다:

```bash
grep -rn -i -B2 -A8 --include='devlog*.md' "검색어" .claude/session/ 2>/dev/null | tail -60
```

파일이 크면 전체를 읽지 말고 grep으로 좁힌 뒤 해당 구간만 `Read` 의 `offset`/`limit` 으로 본다. 회고 요청("이번 주 뭐 했지")이면 타임스탬프로 구간을 잘라 읽고 주제별로 묶어 요약한다 — 항목을 시간순으로 나열하는 건 원본을 읽는 것과 다를 바 없다.

### 결정 기록

기술 선택이나 방향 전환이 있었으면 그 항목에 `**결정:**` 한 줄을 남긴다. 별도 `decisions.md` 를 두지 않는 이유는, 기록 시점이 한 곳이어야 "이건 어디 쓰지"를 매번 판단하지 않아도 되고, 결정 앞뒤 맥락(무슨 작업 중이었는지)이 같이 딸려 나오기 때문이다.

```markdown
## 2026-08-06 17:22 — 인증 방식 확정
**요청:** 세션 인증 어떻게 할지 정하자
**결과:** JWT 대신 서버 세션 채택
**결정:** 서버 세션 사용 — JWT는 즉시 무효화가 안 돼 로그아웃 요구사항과 충돌. 확장은 Redis로 감당.
```

결정 라인에는 **고른 것과 버린 것, 그 이유**를 같이 적는다. "서버 세션 채택"만 남기면 반년 뒤에 "JWT는 검토했었나?"를 또 처음부터 따지게 된다.

결정만 모아 보려면:

```bash
grep -r -B4 --include='devlog*.md' '^\*\*결정:' .claude/session/ 2>/dev/null
```

### 수동 기록

훅이 뽑는 요약은 transcript에서 기계적으로 추출한 수준이라, 중요한 결정이나 실패한 시도의 이유 같은 건 놓친다. 사용자가 "이건 devlog에 남겨줘" 라고 하면 같은 포맷으로 직접 append 한다:

```markdown

## 2026-08-06 17:22 — {한 줄 요약}
**요청:** {사용자가 원한 것}
**결과:** {실제로 한 것과 결과}
**변경:** {파일 목록}
**결정:** {선택이 있었다면 — 고른 것, 버린 것, 이유}
**메모:** {훅이 못 잡는 것 — 시도했다 실패한 접근, 왜 이 방식이 아니면 안 됐는지}
```

기존 내용 위에 이어 붙이기만 한다. 앞선 항목은 건드리지 않는다.

## 4. 프로젝트 브리프 (brief)

"이 프로젝트를 다른 프로젝트/에이전트가 알아듣게 정리해줘", "온보딩 문서 만들어줘" 같은 요청. `/jay-brief` 명령과 같은 일이며, **전체 절차와 템플릿은 그 명령 파일에 있다.** 자연어로 들어왔더라도 결과물은 같아야 하므로, 아래 네 가지만 지키고 나머지는 그 절차를 따른다.

- **`.claude/session/project-brief.md` 하나뿐이다.** 프로젝트당 문서 하나. 주제별로 쪼개지 않는다
- **혼자 완결돼야 한다.** 받는 쪽은 이 저장소를 안 갖고 있을 수 있다. `README 참고` 같은 포인터는 거기서 열 수 없는 주소다. `README.md` 와 `CLAUDE.md` 는 재료로 읽되 내용은 이 파일에 담는다
- **절 순서는 얕은 것부터.** 한 줄 요약 → 무엇을 하는가 → 구조 → 돌리는 법 → 아키텍처와 설계 결정 → 함정 → 최근 흐름 → 지금 진행 중인 것. 위에서 읽다가 충분해지면 멈출 수 있어야 한다
- **파일이 이미 있으면 먼저 읽는다.** 갱신이지 재작성이 아니다. 구조·최근 흐름은 git 에서 새로 뽑고, **아키텍처 결정과 함정은 이어받아 덧붙인다** — 저장소로 복구할 수 없는 유일한 부분이라, 새로 쓰면 그때까지 쌓인 것이 통째로 사라진다

`/jay-new` 와 헷갈리지 말 것. 그건 *내가 하던 작업*을 다음 세션에 넘기는 문서고, 이건 *프로젝트 자체*를 밖으로 설명하는 문서다. 진행 중인 작업은 여기서 맨 마지막 한 절이다.

마무리 출력은 절대경로를 박은 복붙 프롬프트다. 받는 쪽은 다른 프로젝트에서 일하므로 작업 폴더가 다르고, 상대경로는 거기서 의미가 없다.
